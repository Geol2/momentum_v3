# 논문 PDF 번역 설정

PDF를 넣으면 문단 단위로 번역해 원문과 나란히 보여줍니다. 우측 하단 문서 아이콘으로 엽니다.

**PDF에서 글자를 뽑는 일과 스캔본 OCR은 전부 브라우저 안에서 끝나고, 파일은 어디로도
업로드되지 않습니다.** 서버로 나가는 건 번역할 텍스트뿐이고, 그것도 서버 번역을 켰을 때만입니다.

동작 흐름:

```
브라우저: PDF 선택 → pdf.js로 텍스트 추출 (2단 조판 복원)
   → 글자가 거의 없으면 "스캔본" 안내 → tesseract.js OCR (선택, 느림)
   → 원문 언어 자동 감지 → 문단 목록 완성

번역 (둘 중 하나, 서버 경로가 설정돼 있으면 그쪽 우선):

  A. 브라우저 내장 번역기 (Chrome 138+ 데스크톱)
     → Translator API, 키·비용·서버 없음, 기기 안에서 실행
     → 문단 하나씩 순서대로

  B. 서버 번역 (품질이 필요할 때)
     → POST /api/translate (JWT 인증, 문단 3500자씩 나눠서)
     → 백엔드 TranslateService → n8n 웹훅(localhost)
     → n8n → Anthropic Messages API → 번역문 반환
```

## 엔진 두 갈래

| | 브라우저 내장 | 서버 번역 |
|---|---|---|
| 설정 | 불필요 | n8n + 백엔드 환경변수 + 프론트 플래그 |
| 비용 | 무료 | LLM API 종량제 (논문 한 편 수백 원 수준) |
| 동작 범위 | **Chrome 138+ 데스크톱만** | 모든 브라우저 (카톡 인앱 포함) |
| 품질 | 문장 단위 NMT — 초록 훑어보기용. 전문용어·문체가 무너짐 | 문단 문맥·용어 일관성 유지 |
| 파일 이동 | 없음 | 추출된 **텍스트만** 서버로 |

내장 번역기는 첫 사용 시 언어팩을 내려받고, `Translator.create()`가 **사용자 제스처를
요구**합니다. 그래서 원문 언어 감지는 파일을 고른 직후에 미리 해둡니다 — "번역 시작"을
누른 뒤에 감지하면 제스처가 만료돼 생성이 거부됩니다.

---

## 1. 브라우저 내장 번역기만 쓰기 (기본값)

**설정할 것이 없습니다.** Chrome 138 이상 데스크톱에서 열면 바로 동작합니다.
그 외 환경(모바일, Safari, 카톡 인앱)에서는 모달에 "이 브라우저에는 번역 엔진이 없어요"가
뜨고 번역 버튼이 비활성화됩니다. PDF 추출과 OCR은 그런 환경에서도 정상 동작합니다.

## 2. 서버 번역 켜기

### 2-1. n8n 워크플로 임포트

`integration-api-backend/n8n/translate-workflow.json` 을 n8n에 임포트합니다.
노드 구성: `Webhook → 번역 요청 만들기(Code) → Claude 번역(HTTP) → 응답 파싱(Code) → 응답 반환`

자격증명 **두 개**를 만들어 연결해야 합니다 (둘 다 Header Auth):

| 붙일 노드 | 헤더 이름 | 값 |
|---|---|---|
| Webhook | `X-Translate-Key` | 아무 긴 랜덤 문자열. 백엔드 `N8N_TRANSLATE_KEY`와 같아야 함 |
| Claude 번역 (HTTP Request) | `x-api-key` | Anthropic API 키 |

> **Webhook 노드의 Respond를 "Respond to Webhook 노드 사용"으로 두세요.**
> 회의록 녹음 워크플로는 Respond=Immediately지만, 번역은 결과를 받아와야 하므로 반대입니다.
> Immediately로 두면 빈 응답이 즉시 돌아오고 번역문은 영영 도착하지 않습니다.

모델은 `claude-opus-5`, 출력은 **structured outputs(`json_schema`)로 고정**했습니다.
"JSON으로만 답하라"고 프롬프트로 부탁하고 파싱 실패를 재시도하는 것보다 확실합니다.
번역은 추론이 필요 없고 지연·비용만 늘어나므로 `thinking`은 꺼두고 `effort: low`로 돌립니다.

### 2-2. 백엔드 환경변수

| 변수 | 필수 | 설명 |
|---|---|---|
| `N8N_TRANSLATE_WEBHOOK_URL` | ✅ | n8n 웹훅 주소. **localhost로** — 서버 간 호출이라 인터넷에 열 필요가 없습니다 |
| `N8N_TRANSLATE_KEY` | ✅ | 위 Header Auth 값과 동일 |
| `TRANSLATE_TIMEOUT_SECONDS` | | 기본 85. Cloudflare Tunnel의 ~100초 상한 아래여야 합니다 |
| `TRANSLATE_MAX_CHARS` | | 기본 20000. 한 요청에 담을 수 있는 원문 길이 |

미설정이면 `/api/translate`가 503으로 응답할 뿐, API는 정상 기동합니다.

### 2-3. 프론트 플래그

`.env.production` 의 `VITE_TRANSLATE_SERVER=1` 로 바꾸고 다시 빌드합니다.

프론트에 두는 건 **켜고 끄는 스위치뿐**입니다. 웹훅 주소와 API 키는 서버에만 둡니다 —
`VITE_*` 값은 빌드 시 번들에 인라인되어 누구나 읽을 수 있고, 공유 키로는 누가 호출했는지도
알 수 없습니다. 인증은 우리 API가 사용자 JWT로 처리합니다.

## API 계약

```
POST /api/translate     (JWT 필요)
  { "texts": ["문단1", "문단2", ...], "source": "en", "target": "ko" }
→ { "translations": ["번역1", "번역2", ...] }
```

`texts`와 `translations`의 **개수·순서가 반드시 일치**해야 합니다. 어긋나면 백엔드와
프론트 양쪽에서 502로 실패 처리합니다 — 번역문이 원문과 한 칸씩 밀린 채로 조용히
표시되는 것보다 낫습니다.

프론트는 문단을 **3500자씩 나눠 순서대로** 보냅니다. 논문 한 편을 한 요청에 담으면
Cloudflare Tunnel의 ~100초 상한에 반드시 걸립니다. 문단 하나씩이 아니라 묶어서 보내는
이유는 앞뒤 문맥이 있어야 전문용어 번역어가 일관되기 때문입니다.

## 구성 파일

| 파일 | 역할 |
|---|---|
| `src/components/PdfTranslator.jsx` | 모달 UI, 진행률, 결과 보기·복사·저장 |
| `src/lib/pdfText.js` | pdf.js 추출 + tesseract.js OCR (둘 다 동적 import) |
| `src/lib/pdfLayout.js` | 좌표 → 문단 복원 규칙 (pdf.js 비의존 순수 로직) |
| `src/lib/translate.js` | 엔진 두 갈래를 같은 인터페이스로 감쌈 |
| 백엔드 `translate/TranslateService.java` | n8n 웹훅 호출·응답 검증 |
| 백엔드 `web/TranslateController.java` | `POST /api/translate` |
| 백엔드 `n8n/translate-workflow.json` | 임포트용 워크플로 |

`pdfLayout.js`를 따로 뗀 이유는 브라우저 없이 Node에서 실제 논문으로 검증할 수 있게
하려는 것입니다. 조판 판정 규칙도 이 파일 하나만 보면 됩니다.

## 문단 복원 규칙 (pdfLayout.js)

pdf.js가 주는 건 문단이 아니라 좌표가 달린 글자 조각들입니다. 그대로 이으면 2단 조판
논문은 왼쪽 첫 줄 다음에 오른쪽 첫 줄이 붙어 문장이 통째로 뒤섞입니다. 그래서:

1. **가로쓰기 조각만** 남깁니다 — 여백에 90도로 세운 arXiv 도장이 본문에 끼어들지 않게
2. **단 나누기** — 가운데를 가로지르는 조각(제목)은 따로 모아 맨 앞에, 나머지는 좌·우로
3. **줄 묶기** — y좌표가 글자 높이 절반 안이면 한 줄
4. **블록 나누기** — 좌우 끝이 **둘 다** 움직였을 때만. 한쪽만 움직인 건 문단 첫 줄의
   들여쓰기나 마지막 줄이라, 여기서 자르면 멀쩡한 문단이 토막 납니다
   (초록처럼 본문보다 좁게 조판된 덩어리를 갈라내기 위한 규칙)
5. **문단 잇기** — 앞 줄이 단 폭을 못 채우고 끝났거나 다음 줄이 들여쓰기면 문단 끝.
   단 폭은 `max`가 아니라 **80 백분위**로 잽니다 — max로 재면 제목 한 줄이 기준을
   부풀려 본문 전체가 "짧은 줄"로 오인됩니다

## 알려진 한계

- **수식·표·그림 캡션은 깨집니다.** 조각 순서가 PDF 안에서 원래 뒤엉켜 있습니다.
- **회전된 페이지(세로쓰기·가로 스캔)는 지원하지 않습니다.**
- **줄바꿈 하이픈 복원의 부작용** — `inter-\nnational`은 `international`로 잘 붙지만,
  원래 하이픈이 있던 합성어가 하필 그 자리에서 줄바꿈되면 하이픈이 사라집니다
  (`high-level` → `highlevel`). PDF만 봐서는 둘을 구분할 수 없고, 번역기는
  `highlevel`은 알아들어도 `learn- ing`은 못 알아들어서 이쪽을 택했습니다.
- **OCR은 매우 느립니다** (페이지당 수십 초). 텍스트 레이어가 없는 스캔본 전용입니다.
- **내장 번역기는 Chrome 데스크톱 전용**입니다. 모바일·인앱브라우저는 서버 번역이 있어야
  동작합니다.

## 검증 상태

- PDF 추출·문단 복원: 실제 논문 2편(2단 조판 ResNet, 1단 조판 Attention Is All You Need)으로
  Node에서 확인했습니다.
- 프론트 빌드, 백엔드 컴파일: 통과.
- **n8n 워크플로는 실제로 임포트해 돌려보지 않았습니다.** 노드 파라미터는 표준 스키마대로
  작성했지만, 첫 실행에서 오류가 나면 노드 설정을 손봐야 할 수 있습니다.
